## Context

见 `proposal.md — Why`。`llm-privacy-gateway` 与 `llm-pii-cache-concurrency` 后，PII 脱敏已切为全局持久 LRU（`GlobalPiiTokens` 1000+1000）+ `ContextVar` 并发隔离，空体守门改为 `bytes_written`。但全链路仍黑盒：无处可查“某请求是否触发替换、命中哪类、哪条上游、多少 token、是否走 cache、审计是否拦截”。本 change 在不改转发语义的前提下补可观测性：**内存轻量采集（含 latency 环形用于 p50/p95）+ SQLite WAL 日/小时聚合 + 同进程 `/_admin` 单 HTML 大盘（Chart.js 内联）**。约束：Mixin 拆分、锁外网络 I/O、全量 `pytest -q` + ruff 全绿、public repo 无内网信息、单实例 NASRT/Docker 为主。

## Goals / Non-Goals

**Goals:**
- 同进程内完成采集→聚合→展示闭环，首版零新增 pip 依赖、单 HTML（无构建）、首帧可见
- 指标覆盖：PII/凭据脱敏计数与命中率、上游转发与延迟、token usage、审计处置、LRU/守门状态，全部不含明文 PII
- 实时：最近事件环形缓冲（含 `latency_ms`）+ SSE 推送，窗口化查询 `?range=1h|24h|7d|30d`（`1h` 精确分位（低流量标 `≈`）/`24h≈`/`7d≈`/`30d≈`，统一标注）

**Non-Goals:**
- 不做多实例聚合/告警（Prometheus 首版不注册路由，仅预留命名 `credential_proxy_*`，请求返回 `404`，二期再引入 `prometheus_client`）
- 不引入重前端框架（Next/React）与构建链
- 不改 `PII_HOLD_MAX`、LRU、上游重试等现有语义；不新增对外转发 API

## Decisions

### D1 — 单进程嵌入式采集（`_metrics.py` MetricsCollector）

**选择：** 新增 `MetricsCollector` 单例（`proxy.py` 初始化、注入到各 Mixin，`llm-proxy-only.py` / `credential-proxy-only.py` 同路径初始化），**单锁批递增**（热路径 `LOAD-ADD-STORE` 非原子，跨 `await` 让出时丢数；用一把 `asyncio.Lock` 护住整段 `counters+recent_events` 的批递增，**每请求仅一次 `async with self._lock`** 完成全部 `pii_detected_total`/`pii_cache_hit_miss`/`cred_hit_miss`/`requests_total`/`requests_by_status`/`audit_by_*` 与 `recent_events.append`，避免多锁死锁与 `requests`/`latency` 快照不一致；**锁内禁 `await`**——先在锁外收集 `delta={kind:1,...}, latency_ms, status, upstream, is_empty_guard, is_client_gone`，再 `async with self._lock: counters[k]+=delta[k]; events.append(event)`（**两段时长分开标注：① 每请求批递增段（`counters+=delta` + `deque.append`）同步段 <20µs；② 每 5min 快照深拷贝段（`{k:dict(v)}+list(deque)` 约1~2MB）锁内 100~400µs 可接受，两段均禁 `await`**——验收 `grep -A2 "async with self._lock" | grep -c await ==0` 只验证禁 await，不约束拷贝时长；若递增块内含 `await` 则死锁/阻塞 5ms@100RPS=50% 事件循环））。**跨 hour/date 边界丢数闭环（覆盖式 UPSERT 的已知反例）：** `QueueFull` 丢弃最老快照时，若被丢快照属于上一 `date/hour` 窗口（如 23:58 丢弃 → 00:03 新键不覆盖旧键），该窗口增量永久丢失。**修法：** flush 时按快照自身 `date/hour` 拆键落盘（不是用"当前时间"键），且 `QueueFull` 丢弃时优先保留"整点±5min 内（跨窗口候选）"快照——`dropped` 时若队首为跨窗口候选则 `get_nowait` 丢非候选最老，否则丢最老并计 `dropped_snapshots`；首版最小实现：flush 对每个快照用其 `snapshot_ts` 对应的 `date/hour` 键 UPSERT（覆盖式），并对 `first_dropped_ts/last_dropped_ts` 窗口做一次补偿 UPSERT（该窗口键已存在则保留，缺失则补）——保证跨窗口增量不丢（允许≤1个快照窗口的延迟）。**`sanitize_kind` 抽为独立工具函数**（`_metrics.py` 或共享 `utils/`）：输入 `raw_kind` + `custom_names` 集合，输出归一的 `kind` label（`len>32 | "__" in raw | "\x00" in raw → "custom_other"`，大小写归一后查 `BUILTIN_KINDS={phone,id_card,email,bank_card,ipv4,ipv6,api_key}` 与自定义小写集合，否则 `custom_other`），三处落盘前必经（`scan` 计数、`register` 计数、`metrics.sqlite UPSERT json.dumps` 前），`audit_by_rule` 存 `reason` 非 `pattern`。**快照与落盘用有界 `queue.Queue(maxsize=5)`（线程安全，替代 `asyncio.Queue` 跨线程不安全，或经 `loop.call_soon_threadsafe` 入队） 单写者串行化**（事件循环内深拷贝后 `put_nowait` 到队列，`ThreadPoolExecutor(max_workers=1, thread_name_prefix="metrics-writer")` 单 worker 消费（与 p95 隔离：p95 用独立专用 `ThreadPoolExecutor(max_workers=1, thread_name_prefix="p95-worker")`（或等效隔离的 `asyncio.to_thread` 专用池）**独立于** `metrics-writer` 单 worker，避免写盘排队），`put_nowait` 遇 `QueueFull` 时 `get_nowait` 丢最老再入队并计 `dropped_snapshots` + `first_dropped_ts/last_dropped_ts` 暴露到 `health`（覆盖式快照的丢弃不丢数——累计快照同窗口下一周期覆盖（跨hour/date边界反例:23:58丢弃→00:03新键不覆盖旧键，需整点±5min优先入队或双写），`first_dropped_ts` 辅助排障），递增时 `logger.warning("metrics queue full, dropped=%d", dropped)` 告警，逐条 `INSERT ... ON CONFLICT DO UPDATE SET col=excluded.col` **覆盖式**更新（快照为累计总量直接覆盖，单写者串行无需增量累加，避免 `col+excluded.col` 的持续双计；增量方案需维护 `last_snapshot` 反而易错已废弃），避免 SQLITE_BUSY 与覆盖丢数；**深拷贝**：`snapshot={k:(dict(v) if isinstance(v,dict) else v) for k,v in self._counters.items()}` + `list(self._events)`，防 `run_in_executor` 线程 `json.dumps` 时主循环撕裂（拷贝约1~2MB每5min，锁内100~400µs可接受，同步段<20µs））。**延迟分桶：** 固定 12 桶 `LATENCY_BUCKETS=[10,25,50,100,200,400,800,1500,3000,5000,10000,Inf]` ms，`metrics_bucket(latency_ms)` 命中首个 `>=latency` 桶 `+1`，聚合查询时桶 `SUM` 后逆分位取首个累计 `>=0.95*total` 的桶中位作为 `p95≈`。环形缓冲 `recent_events: deque(maxlen=10000)` 用同一 `asyncio.Lock` 保护且每条含 `latency_ms` + `ring_coverage_s/is_precise` 元数据（`is_precise = (now - oldest_ts) >= 3600 and len(events) >= 100`，高 TPS 下 50 RPS 仅 200s 留存时自动标 `≈`——**`50 RPS/100 RPS 时 1h 窗口永为 `≈` 属设计预期**，非缺陷；低流量 `ring_len<100` 时方差大亦标 `≈`；`len==0` 时 `p95=None`）。**埋点位置（口径拆分）：** `_pii.py: PiiDetector.scan` → `pii_detected_total{kind}`（检测到）与 `_token.py: GlobalPiiTokens.register` → `pii_cache_hit/miss`（命中已注册复用/新建，PII 淘汰分支 `while len(table_p2t)>PII_MAX_ENTRIES: popitem(last=False)` 时按实际弹出条数批量 `pii_lru_evictions+=n`（两表 `pii_p2t/resp_p2t` 各自触发均累加，批量淘汰不丢数））分离；`TokenMixin._register_secret` + `_llm.py._redact` 命中 → `cred_hit/miss`（`_redact` 快照命中亦计 `hit`，按请求 `out!=in` 计 1 而非替换次数）与 `cred_lru_evictions`（`len(pwd_to_token)>=MAX_TOKEN_ENTRIES` 分支内 `next(iter(pwd_to_token))` 取最老并 `pop(oldest)` 时 `+1`，文案旧称 `popitem(last=False)` 已对齐真代码；`cred_hit/miss` 覆盖 `TokenMixin._register_secret` 新建/复用 + `_llm.py:_redact(snapshot_p2t)` 快照命中 `out!=in` 显式判定，按请求计 1 而非替换次数）；`_llm.py: handler`（上游 `port` 主键维度、`tail/stream` 为事件维度不进主键，`requests_total{status}` 每条请求计 1（重试不计多次，落盘为 `requests INT` 总量 + `requests_by_status JSON` 分布）、`latency_ms/ttft/bytes_in/out`、`empty_guarded`、`client_gone`、token `usage` 归一）——**流式与非流式两条响应路径均埋点**（非流式 `upstream_resp.read()` 分支也记 `requests_total/latency/bytes`），抽 `is_chat_tail(tail)`（对 `tail.rstrip('/')` 后 `endswith(chat/completions|v1/messages|v1/responses)`，避免 `/v1/responses/` 漏判），**`requests_total` 与 `latency` 对所有 tail 计数，`upstream` 分组对非对话归 `other` 不丢数**；**空体守门两条路径均计 WHERE hour>=?` 单条 SQL 拉全量后 Python `json.loads` 分组求和，避免 N+1 按 upstream 循环）。**埋点不遗漏：** `resp_p2t` 响应侧还原不参与 `pii_cache_*` 计数（仅请求侧检测计）。**关闭衔接：** `proxy.py: shutdown` 在 `runner.cleanup` 前 `await proxy.collector.close()`（`try/except CancelledError` 保护，`close()` 内 `cancel 定时器 + 最终 flush + 等待 executor 完成 + PRAGMA wal_checkpoint(TRUNCATE) + 重 chmod 0600`），轻量双入口同加 `SIGTERM` handler + `finally: await collector.close()`；`health` 补充 `first_dropped_ts/last_dropped_ts` 与 `audit_pending_total` 瞬态标注“重启归零”。

**备选：** 独立 sidecar 进程 / 外置 TSDB —— 部署与 IPC 成本高，单实例场景无收益。

**理由：** 与现有 Mixin 单例、`DATA_DIR` 落盘风格一致；热路径仅单锁批 `+=1` 与 `deque.append`，队列单写者保证快照一致性，`ruff` 可静态检查未污染。单锁批递增避免多锁开销与死锁，深拷贝防线程撕裂，有界队列防 OOM，固定 12 桶 `latency_buckets` 使 `1h/24h/7d/30d` 均自包含且可逆分位，覆盖式 UPSERT 避免增量双计。

    if q and request.path != '/_admin/events/stream':

### D3 — 单 HTML 无构建大盘（静态内联 + 降级）

**备选：** React/Next 构建产物 —— 与“零依赖、单文件可审计”相悖。

**理由：** 用户偏好“简单直接、schema 精简”；单文件便于 `docker exec cat` 审计与离线可用。统一 `≈` 标注避免误导。

### D4 — 不含明文的可观测性契约

**选择：** 所有对外 JSON/HTML 仅暴露 `kind/count/placeholder_preview([REDACTED:phone])`，不含原始 PII；`recent_events` 存**先 `_audit_live_redact` 脱敏后 `truncate(120)`** 的单一路径摘要（`rec=redact_summary(raw,120)`，脱敏在持久化之前完成，截断边界半字符保护，PII 明文不落盘；单测注入 `120+64` 长 `sk-` 验证无明文残留）；自定义正则名白名单**集中实现** `sanitize_kind(raw, custom_names)`：`len>32 | "__" in raw | "\x00" in raw → custom_other`，大小写归一后查 `BUILTIN_KINDS={phone,id_card,email,bank_card,ipv4,ipv6,api_key}` 与自定义小写集合，否则 `custom_other`，三处落盘前必经（`scan` 计数、`register` 计数、`metrics.sqlite UPSERT json.dumps` 前）；`audit_by_rule` 存 `reason` 非 `pattern`，避免规则名含 PII；`metrics.sqlite` 落盘目录经 `docker-compose.yml` 卷挂载 `${DATA_DIR:-./data}:/data`（与 `tpm:ro/db:ro` 叠加验证不遮蔽，或改子目录 `/data/metrics`），`docker-entrypoint.sh` 负责 `mkdir -p /data && chmod 700 /data && chown credential-proxy:credential-proxy /data`，DB 文件与 `-wal`/`-shm` 均 `0600`（建表前 `os.umask(0o077)` 或 `open; os.chmod` 紧邻，建表后立即 `os.chmod` 且每次 `wal_checkpoint` 后重 chmod，`docker-entrypoint.sh` 追加 `chmod 700 "$DATA_DIR"` 闭环 `umask 022` 窗口期；`umask` 恢复在 `finally`）。

**备选：** 明文落盘便于排障 —— 与隐私目标冲突。

### D6 — 流式双路径埋点与 JSON-aware 三态（v0.9.16-25 基线对齐）

**选择：** `_llm.py` handler 的 SSE 分支自 v0.9.24 起按 `is_dialog_tail && (active_t2p || _pii_active() || audit_enabled())` 分流 slow 链（JSON-aware 流式还原）与 fast 链（`active_t2p==0` 且无 PII/审计时整行透传，默认热路径）。**埋点必须在 handler 外层统一收集**（请求开始记录 `t0/upstream/status`，结束 `try/finally` 记 `latency/bytes`），不得只挂在 slow 链——否则 fast 链（绝大多数正常请求）漏计 `requests_total/latency`。**`sse_events` 按 SSE 事件块计**：`event:`/`id:` 行与 `data:` 行同块写出（`slow_event_pending`/`fast_event_pending` FIFO 拼装，v0.9.23-25），每 data 事件块计 1；合成终止事件（`_build_truncated_event*`/`_fast_truncated`，v0.9.16 起）单列 `truncated_total` 不计入 `sse_events`。**JSON-aware 三态**：脱敏/还原走 `orjson` + 叶子级最小回退（v0.9.10-15），计数 `json_aware_success_total`/`json_leaf_fallback_total`/`json_full_fallback_total` 三态，废弃旧 `plain str.replace` 口径。**`empty_guarded` 扩展**：v0.9.14 起非流式 `_is_invalid_json` 判定的非 JSON 响应亦转 502，单列 `invalid_json_guarded` 与空体守门分开计数。**token usage 需新增解析**：当前仅透传上游 `usage` 无解析，非流式从 `upstream_resp.read()` body JSON 提取，流式从 `stream_options.include_usage` 末块或 `usage` delta 聚合；有则记无则 `unknown` 不估算。**归一函数 `normalize_usage(obj, protocol)` 输出统一 `{prompt, completion, total, input, output, cached_read, cached_write, unknown}`**，其中缓存维度映射（成本核算关键，缓存命中输入 token 按折扣价计费）：

| 协议 | 输入 tokens | 输出 tokens | 缓存命中 cached_read | 缓存写入 cached_write |
|---|---|---|---|---|
| OpenAI Chat (`/v1/chat/completions`) | `usage.prompt_tokens` | `usage.completion_tokens` | `usage.prompt_tokens_details.cached_tokens` | 无（`0`/缺省） |
| Anthropic (`/v1/messages`) | `usage.input_tokens` | `usage.output_tokens` | `usage.cache_read_input_tokens` | `usage.cache_creation_input_tokens` |
| OpenAI Responses (`/v1/responses`) | `usage.input_tokens` | `usage.output_tokens` | `usage.input_tokens_details.cached_tokens` | 无（`0`/缺省） |

流式需请求侧注入 `stream_options: {"include_usage": true}`（不覆盖已设）否则 OpenAI Chat/Responses 不返回 usage；**注入仅限 OpenAI Chat/Responses（`protocol in ('openai','responses')`）且 `is_stream==true`，Anthropic `/v1/messages` JSON Schema 严格、携带 `stream_options` 即 `400 invalid_request_error: extra field`，严禁注入**；注入实现：`json.loads(out_body)` 后 `obj.setdefault("stream_options",{}).setdefault("include_usage", True)`（浅覆盖不整体替换，客户端显式 `include_usage:false` 保持 false，已含 `stream_options:{"extra":1}` 时合并保留），非 JSON 体 `try/except` 原样放行；Anthropic 流式 `message_start` 携带输入+缓存、`message_delta` 携带输出，两事件聚合。**`total` 语义**：`total = obj.get("total_tokens") or obj.get("total") or (input+output)`（Anthropic/Responses 原生无 `total_tokens`，缺失时求和，两值均缺则 `unknown` 不估算）。**null 守卫**：`cached_read = (obj.get("prompt_tokens_details") or{}).get("cached_tokens", 0)`（OpenAI 无缓存命中时 `prompt_tokens_details: null`，`.get()` 直接调用抛 AttributeError 会丢整条请求计数）。**快链提取**：fast 链 `_fast_emit_data`（`_llm.py:4560`）已对每个 data 块 `json.loads`（为 `finish_reason`/终止判定），slow/fast 双链各设 `last_usage` 捕获 `usage` 字段（OpenAI Chat 末块 `usage` / Responses `response.completed.response.usage` / Anthropic `message_start`+`message_delta` 聚合），在 `seen_terminal` 后继续读 1 块聚合并交外层 `try/finally` 统一入 `tokens`，`bytes_written` 守门/`truncated` 合成事件后仍计。**`tokens JSON` 按 `model` 分桶**：取请求 `body.model`（响应若回 `model`/`usage.model` 则以响应为准），无则 `unknown_model`，聚合时 `tokens JSON` 内部按 model 分桶 `{"gpt-4o": {...}}` 不新增主键列。`cached_read/cached_write` 归入 `tokens JSON` 供 `/_admin/metrics` 与大盘成本核算展示；**`cached_write` 为 Anthropic 写入缓存的输入 token（`cache_creation`），非命中，成本按写入价（约 1.25x）计费，命中后后续请求的 `cached_read` 才按折扣价（约 0.1x）计费，两者价差 10 倍不得混同**。

**备选：** 只在 slow 链埋点 / 按 data 行计事件 —— 漏计 fast 热路径与 SSE 块语义不符。

**理由：** 双路径是 v0.9.24 起的真实执行结构，外层统一收集保证计数完整；SSE 块计数对齐下游 SDK 解析语义（`JSONDecodeError` 正是由拆块引起，v0.9.23）；三态计数让 JSON-aware 降级路径可观测，避免误导性的 `plain str.replace` 度量。

## Risks / Trade-offs

- [计数与真实转发不一致/口径重叠] → Mitigation: `pii_detected_total` 与 `pii_cache_hit/miss` 分离，`cred_hit` 含 `_redact` 快照命中（按请求计 1）；计数紧贴替换/转发的同一回调内单锁批递增，`try/finally` 保证落数；单测对照 `audit.log` 条数
- [SQLite 锁竞争/半写] → Mitigation: 单锁批递增 + 有界 `Queue(5)` 单写者串行 UPSERT（WAL + `busy_timeout=5000` + `synchronous=NORMAL` + `wal_autocheckpoint=1000`），覆盖式 `ON CONFLICT DO UPDATE SET col=excluded.col`（累计覆盖，单写者避免增量双计；QueueFull 丢弃是覆盖式快照不丢数（同窗口内，跨边界需窗口分段））；深拷贝防撕裂；磁盘满 `ENOSPC` 降级内存-only（捕获 `OSError as e if e.errno==28` 或 `sqlite3.OperationalError` 含 `disk I/O error`/`database or disk is full`，统一置 `health.sqlite_ok=false` + `logger.error`；恢复后仅从当前累计续写，不回补） 且 `health.sqlite_ok=false`；5min + 优雅关闭双 flush（`await collector.close()` 含 `wal_checkpoint(TRUNCATE)` + 重 chmod）；30天/7天滚动（滚动 `DELETE` 不做 per-flush `VACUUM`，碎片化靠月度 `VACUUM` 或 `auto_vacuum=INCREMENTAL`）；正常退出丢 0，`kill -9`/断电丢 ≤5min+WAL 未 checkpoint 页；管理接口 `10/min/IP` 超限 `429 + Retry-After`（`synchronous=NORMAL + wal_autocheckpoint=1000`）已在 README 明示并附 12 桶误差表（最差约30.4% @[800,1500)（等比约33%） 中位）。`latency_buckets` 固定 12 桶可逆分位，`requests_by_status` 保留状态分布
- [Admin 接口未鉴权外泄/时序侧信道] → Mitigation: `OBSERVABILITY_ADMIN_TOKEN` 必填（未设 `SystemExit` + `logger.critical`），不与 `CREDENTIAL_ADMIN_TOKEN`/`MATRIX_ACCESS_TOKEN`/文件 token 重名（空值短路交叉检查 + `401` 不互认），不信任 `X-Forwarded-For` 且不加载 `Forwarded` 中间件，`401` 前不触 DB，请求头 `?access_token` 仅 SSE 回退且掩码日志 + `history.replaceState` 清 URL + 反代过滤
- [CDN 不可用导致图表空白] → Mitigation: `Chart.js` 内联打包，`Chart is not defined` 时自动切 SVG 降级，保证数值与表格始终可见；CSP `script-src 'self'` 场景同样降级（`addEventListener` 替代 `onclick`）
- [埋点遗漏/p95不可算] → Mitigation: tasks 验收 `grep -rn collector.` 覆盖 5 文件 + `grep -rn latency_ms`；`recent_events deque(10000)` + `latency_buckets` 支撑 `1h` 精确/`24h≈/7d≈/30d≈`；`requests_total/latency` 全 tail 计，`upstream` 主键仅 `port`；流式与非流式两条响应路径均埋点；`ring_coverage_s` 动态 `≈`
- [流式双路径漏埋点/fast 热路径不计] → Mitigation: 埋点在 handler 外层统一收集（`try/finally`），slow/fast 双链共享同一计数出口；`sse_events` 按 SSE 事件块计（`event:`+`data:` 同块 1 事件）；合成终止单列 `truncated_total` 不入 `sse_events`（tasks 1.3/4.1a 验收含 fast 链断言）
- [占位符注入污染计数] → Mitigation: `inject_placeholder_prompt` **实例方法**（`_pii.py:1208` 带 `self`，请求作用域无跨请求状态、锁外同步；须经 `LlmMixin+PiiMixin` 实例调用，非模块级纯函数）不计 `pii_detected_total`/`bytes_in`，注入前禁二次扫描；单列 `placeholder_prompt_injected_total` + `health.placeholder_prompt_enabled`（spec 脱敏计数 Requirement + scenario）
- [JSON 半写/截断先脱敏后截断/ label 爆炸] → Mitigation: `redact_summary` 先脱敏后 `truncate(120)` 单一路径；`sanitize_kind` 集中三处必经 + `custom_other` 归一；`metrics.sqlite` `0600`（含 `-wal/-shm`）+ `user_version=1`

## Migration Plan

1. 合并本 change 后重建 Docker 镜像 `ghcr.io/keivry/credential-proxy`；部署时新增必填 env `OBSERVABILITY_ADMIN_TOKEN`（与 `CREDENTIAL_ADMIN_TOKEN`/`MATRIX_ACCESS_TOKEN`/`DATA_DIR/admin_token` 不同值），`docker-compose.yml` 补 `${DATA_DIR:-./data}:/data` 卷挂载（与 `tpm:ro/db:ro` 叠加验证，先挂父卷再挂子 `ro` 或用 `/data/metrics` 子目录避免遮蔽）；`DATA_DIR/metrics.sqlite` WAL 自动建表，`0600`（`-wal/-shm` 同 `0600`），`chmod 700 /data`，`hourly_agg` 7天滑动，`volumes` 顺序 `${DATA_DIR:-./data}:/data` 父卷在前、`tpm:ro/db:ro` 子卷在后（`docker compose config` 验证不遮蔽）

3. 回滚：直接回退镜像，`metrics.sqlite` 可保留或删除，无数据迁移；过渡期可 `OBSERVABILITY_DISABLE=1` 显式禁用 `/_admin` 而非 `SystemExit`（二期收紧，已入 spec，仅作过渡逃生开关，生产仍以必填校验为准）
