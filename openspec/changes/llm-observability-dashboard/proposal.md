## Why

两轮 change（`llm-privacy-gateway` 与 `llm-pii-cache-concurrency`）已上线：PII 全局持久 LRU 解决了 cache 命中暴跌，并发用 `ContextVar` 隔离 + `bytes_written` 守门解决了空流 `JSONDecodeError`。其后（dashboard 文档定稿 `6cfd02f` 之后）又完成 `fix-json-nested-restore` / `json-leaf-fallback-orjson`（JSON-aware 全链路：orjson + 叶子级最小回退，v0.9.10-15）、`pii-gateway-hardening`（传输层/终审闭环 v0.9.17-20）、`pii-placeholder-prompt`（脱敏后占位符说明注入 v0.9.21-22）与 v0.9.23-25 流式协议修复（slow/fast 双路径、`event:`/`data:` 同块写出、合成终止事件、CR-only 根治）。但全链路仍黑盒：PII 是否被替换为 `__PII_*__`、各上游各自转发多少、token/缓存命中多少、上游输出多少、审计拦截多少，全部黑盒——无法验证脱敏生效、无法做成本/故障归因、无法调优 `PII_HOLD_MAX` 与 LRU。本 change 的指标口径 SHALL 与当前实现基线（HEAD=v0.9.25：流式双路径、占位符注入、JSON-aware 三态）对齐。

## What Changes

- **新增嵌入式指标采集层**：在 `PiiDetector` / `GlobalPiiTokens` / `TokenMixin` / `LlmMixin` / `AuditMixin` 的关键路径植入无阻塞计数，产出请求级 `recent_events` 环形缓冲（含 `latency_ms` 用于 p50/p95，`1h` 精确分位、低流量标 `≈`、`24h/7d/30d` 均标 `≈`）+ 进程级聚合计数，落盘 `DATA_DIR/metrics.sqlite`（WAL 模式，`daily_agg` 日聚合 15 列完整（30天滚动，含 `pii_hits/miss`/`cred_hits/miss`/`audit`）+ `hourly_agg` 7天滑动小时聚合 9 列轻量子集（`pii_hits/miss`/`audit` 仅日表保留），每 5min 原子快照覆盖式 UPSERT（`INSERT ... ON CONFLICT DO UPDATE SET col=excluded.col`，累计快照直接覆盖，单写者串行避免双计，深拷贝防撕裂），30天/7天滚动（滚动 `DELETE` 不做 per-flush `VACUUM`，碎片化靠月度 `VACUUM` 或 `auto_vacuum=INCREMENTAL` 二期可选），不存明文 PII；两表均含 `latency_buckets JSON`（固定 12 桶 `10/25/50/100/200/400/800/1500/3000/5000/10000ms +Inf`，最差桶中位误差约30.4% @[800,1500)（等比约33%） 标 `≈`）支撑 `1h精确(50 RPS+ 时 `≈` 属预期，`is_precise=(now-oldest_ts)>=3600 and len>=100`)/`24h≈`/`7d≈`/`30d≈` 统一近似，`requests_by_status JSON` 保留 `status` 分布；`1h` 的 `sorted` 放独立专用 `ThreadPoolExecutor(max_workers=1, thread_name_prefix="p95-worker")`（或等效隔离的 `asyncio.to_thread` 专用池）**独立于** `metrics-writer` 单 worker，避免写盘排队；磁盘满 `ENOSPC` 时降级为内存-only 且 `health.sqlite_ok=false` 不拖垮代理（恢复后仅从当前累计续写，不回补丢失窗口）；`queue.Queue(maxsize=5)`（线程安全） 满时 `get_nowait` 丢最老再入队并计 `dropped_snapshots` + `first_dropped_ts/last_dropped_ts`）**。口径与 v0.9.25 实现基线对齐：① `pii-placeholder-prompt` 注入的 system 说明文本（`inject_placeholder_prompt`，位于 `_pii.py`，请求侧脱敏后、转发前注入）不计入 `pii_detected_total`/`bytes_in`，注入前禁止二次 PII 扫描，注入发生与否单独计 `placeholder_prompt_injected_total` 并在 `/_admin/health` 暴露 `placeholder_prompt_enabled`；② 流式响应按 slow/fast 双路径（`_llm.py` handler 内 `is_dialog_tail && (active_t2p || _pii_active() || audit_enabled())` 分流，v0.9.24 起）分别计数 `sse_events`，`event:`/`id:` 与 `data:` 同块写出（`slow_event_pending`/`fast_event_pending`，v0.9.23-25）按块计 1 事件，合成终止事件（`_build_truncated_event*`/`_fast_*`，v0.9.16 起）单列 `truncated_total` 不计入 `sse_events`；③ JSON-aware 全链路（orjson + 叶子级最小回退，v0.9.10-15）计数按成功/叶子回退/全量回退三态（`json_aware_success_total`/`json_leaf_fallback_total`/`json_full_fallback_total`），废弃旧的 `plain str.replace` 度量口径；④ `cred_hit/miss` 按请求 `out!=in` 计 1（与 `_redact`/`_register_secret` 对齐），`pii_detected_total` 按次、`pii_cache_hit/miss` 按值，不混用。
