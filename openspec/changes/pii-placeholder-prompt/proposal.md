## Why

启用 PII 脱敏（`PII_REDACTION_ENABLED`）后，请求中的敏感明文（手机号、IP 地址、身份证号、银行卡号、API key 等）会被替换为 `__PII_<seq>_<rand8>__` 占位符，凭据被替换为 `__VG_CRED_<seq>__` 占位符，随后透传上游 LLM。当前实现是纯「替换-还原」机制：**上游 LLM 只看到裸占位符，没有任何说明告知其含义**。

对格式敏感的 PII（如 IP 地址 `192.168.1.100` → `__PII_3_9f2a1c77__`），占位符形态与原值差异巨大，上游 LLM 可能：

- 把占位符当作**输入格式错误**（"这不是合法 IP"），触发校验/纠错逻辑，甚至"好心修正"为 `0.0.0.0` 等合法形态；
- 推断或补全占位符内容（"用户可能想填 IP，我帮他补一个"），伪造出不存在的数据；
- 在 tool call 参数（如 `{"phone": "__PII_1_ab12cd34__"}`）中改写占位符，导致下游还原失配，明文永久丢失（改写后的值不在 `pii_t2p` 映射中，无法还原）。

不告知上游模型这些占位符的含义，等于把「原样保留」的希望完全寄托在模型的偶然行为上。

## What Changes

在 PII 脱敏**实际发生**时（请求侧替换产生至少一个 `__PII_*__` 或 `__VG_CRED_*__` 占位符），向转发给上游的 `messages` 中**注入一条说明提示词**，告知模型这些标记是安全网关的脱敏占位符，请原样保留、不要校验格式、不要改写或补全。

具体变更：

- 新增环境变量 `PII_PLACEHOLDER_PROMPT`（默认开启，`1`/`true`/`yes` 启用；`0`/`false`/`no` 关闭），控制是否注入说明提示词；
- 新增环境变量 `PII_PLACEHOLDER_PROMPT_TEXT`（可选），自定义提示词文案；未设置时使用内置默认文案（中文，可自定义覆盖）；空字符串/空白视为未设置，回落内置文案；
- 注入逻辑位于请求侧 PII 脱敏完成之后、转发上游之前；仅当本次请求**实际产生占位符**时才注入，不脱敏则零注入（不污染 prompt、不消耗 token）；
- 注入位置：**追加到现有 system prompt 末尾**（若消息序列首条为 system 消息；多条 system 时仅追加第一条），否则**新建一条 system 消息插入头部**（若消息序列为空则作为唯一消息）；三种协议（OpenAI `chat/completions`、Anthropic `/v1/messages`、Responses API）统一适配，兼容 `content`/`system` 为数组（多部分 blocks）的结构；
- 响应侧还原逻辑不变：模型回显占位符 → 还原为明文（现有机制，不受本变更影响）。

默认提示词文案（推荐版，中文）：

> 说明：消息中形如 `__PII_*__` 和 `__VG_CRED_*__` 的标记是安全网关的敏感信息脱敏占位符，代表被替换的原始值（如手机号、IP 地址、银行卡号、密钥等）。请原样保留这些占位符（包括 `content` 与 `tool calls`/`function` 参数中的）：不要修改格式、不要校验其合法性、不要推断或补全内容，也不要视为输入错误。它们不是格式问题，直接使用即可。

## Capabilities

### New Capabilities

- `pii-placeholder-prompt`: 启用 PII 脱敏时，在实际发生脱敏的请求中向上游 LLM 注入占位符说明提示词，防止格式敏感型占位符被误判为格式错误、被改写或补全。

### Modified Capabilities

<!-- 无：现有 pii-redaction 能力的行为契约不变（仍是替换-还原），本变更只新增注入机制。 -->

## Impact

- `_llm.py`：请求侧 PII 脱敏后、转发前判定占位符（复用现有 `has_cred`/`has_pii` 快速路径）并注入说明提示词（新增注入函数，三协议适配，含数组结构分支）；
- `_pii.py`：内置默认文案常量（供 `PII_PLACEHOLDER_PROMPT_TEXT` 未设置/非法时兜底）；
- `proxy.py`：`_init_pii` 解析新增环境变量 `PII_PLACEHOLDER_PROMPT` / `PII_PLACEHOLDER_PROMPT_TEXT`（含长度/形态校验）；
- `README.md`：环境变量表新增两项；
- 测试：新增注入逻辑单元测试 + 三协议集成测试（注入/不注入/自定义文案/关闭开关/数组结构/非 JSON body）；`pytest` 全量 + `ruff check`/`format --check` 必须通过；
- 无 API 破坏性变更；无 Docker/部署变更（仅新增 env，默认开启）。
